# Admin moderation, audit, reconciliation and support decisions

2026-10-31. Preserve existing UI/router/services. Global product moderation is independent of seller active state: admins block/unblock with reason and expected product version; seller writes cannot clear it. Blocked listings excluded from discovery, direct public lookup, cart quote, inventory reservation and order placement. Existing orders remain immutable; no cancellation/refund implied. Admin product lists cursor-paginated across shops; no broad full download. Taxonomy reactivation keeps IDs/slugs and requires active parent for subcategory activation.

Append-only application audit entries record authenticated actor/action/target/version/time and minimal allowlisted metadata for new moderation, taxonomy reactivation and support mutations. No tokens, raw bodies, customer address/phone/email, payment secrets, receipt codes or support conversation text. Audit explorer admin-only, signed cursor and exact filters; coverage starts with this release, no historical completeness or tamper-proof database guarantee claimed.

Support: existing one-ticket-per-suborder preserved. Buyer/admin conversation stored separately, paginated, actor role only; body rendered as text, no attachments. Message idempotency key avoids duplicate sends, expected ticket version serializes replies/status/reopen. Buyer can access only owned ticket. Resolved ticket accepts explicit reopen with reason, not silent reply. Reopen appends a message/history event, increments version and clears current resolution note (history retained). Search uses escaped literal terms across known ticket/shop/order/description/current-note fields; access filters precede results. No regex input, no refund/order status mutation. Message text is not audit log metadata.

Confirmed settlement scope: read-only reconciliation, no commission, payout cycle, transfers, available balance or paid/settled assertions. List immutable shop suborders with original amount, cancellation, actual recorded cash, captured online allocation and refund status. Distinguish seller vs delivery collector where recorded. These are operational order allocations, not provider bank settlement proof. Test orders excluded; no production infra/keys changed. Payout/cash remittance actions remain unavailable until policy and ledger/transfer integration exist.
