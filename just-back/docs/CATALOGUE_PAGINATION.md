# Area-first catalogue pagination design
Public list services return one bounded page (24 items) and read existing cursor/total response headers. Infinite queries key every area/GPS/filter/sort/shop selection; no previous-area placeholder data. Category filtering/sorting remains server-side, never limited to loaded items. Homepage/categories loaders fetch taxonomy only; area-scoped shop/product previews load after selection. Search/product/shop catalogues expose explicit Load more; next-page errors preserve existing records and support retry. Category discovery totals from server, category tiles omit incomplete per-category counts rather than false zeros. Product detail hydration fetches only its owning shop through a bounded public by-IDs API; page hydration batches up to24 owners. No full catalogue apiAll in public services. Existing demo mode remains local and labelled.
