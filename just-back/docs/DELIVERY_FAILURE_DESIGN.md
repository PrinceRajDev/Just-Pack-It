# Delivery exception handling — 2026-10-31

Preserve partner-claims policy. Admin may release a claimed pre-pickup task back to queue only after explicit goods-at-shop confirmation, reason and expected version. Assignment is removed, old partner activeTask released atomically, old capabilities revoked. Audit/history retain prior partner. No forced post-pickup reassignment or automatic timeout cancellation.

After pickup admin requests return-to-shop with reason/version. Task remains assigned, cannot dispatch/complete or issue buyer receipt while returning. Owning seller must acknowledge actual returned goods, partner ID, version and an explicit all-items-sellable restock decision. Only then cancel this shop suborder, release partner, optionally return exact committed stock once and request captured online refund. Unsellable goods never auto-restock. Pre-pickup admin cancellation similarly requires goods-at-shop and explicit restock choice. Existing confirmed cash or any buyer receipt confirmation blocks cancellation/return automation and requires separate manual financial investigation. No client payment status, price, refund amount or stock increment accepted.

Cancellation verifies committed inventory proof/line identity before any stock decision; restock exact frozen quantities from server lines, never names. Original totals immutable, cancelled amount and due derived by existing order DTO. Prepaid refund is only requested via existing durable refund model; no provider call or claimed payout. Cancellation/release and concurrent pickup/completion serialize on order/partner documents. Expected version and last successful command fingerprint make immediate retries safe without reapplying stock/refund. Partner role/ownership, seller ownership and admin role checked server-side; revoked partners lose active detail/contact/action access.

Admin exception queue includes reported issues and claimed/returning tasks so no-show tasks are actionable without a partner report. Queue is bounded/paginated and exact task lookup is available. Clear/resume an issue only on claimed/picked_up/out_for_delivery, increments version, preserves prior reports in audit, cannot mark delivered or erase cash. Return request is not delivery success. Public buyer DTO exposes only deliveryState, never partner account/contact or raw internal notes. All operations audit minimal action/target/version, notifications contain no receipt secrets or address. Rollout remains defaultoff; no production database or infrastructure change.
