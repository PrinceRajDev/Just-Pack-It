# Delivery pin design
Optional address location GeoJSON Point, coordinates [longitude,latitude], validated server-side. null explicitly clears pin; existing addresses without pin keep current pincode-based coverage and show pin not checked. Address edit uses existing owner/version checks; order snapshot includes saved pin and is immutable after placement. Pin is user supplied, not verified physical identity/address. Seller-delivery with pin requires accurate shop location and straight-line distance <=6 km plus active assigned-area pincode coverage. Same check in fulfilment review and placement; pickup unaffected, platform delivery still unavailable. No client distance/verified flag accepted. Map is optional explicit load, Leaflet with attributed OpenStreetMap standard tiles; no offline/prefetch or geocoder. OSM tiles are best effort without SLA; tile provider policy/capacity must be reviewed before scale. Text address plus explicit user pin confirmation; no silent GPS save.


Implemented: address owned CRUD add optional location/null removal, transactional placement snapshot, shared seller-delivery radius checker used by fulfilment and placement. Frontend DeliveryPinEditor/DeliveryPinMap optional lazy map with explicit GPS, click/drag or keyboard inputs, required pin confirmation reset after edits, preserve old pin on failed GPS. GPS discovery confirmation seeds a draft pin but still requires user confirmation. SavedAddresses handles optional structured field without string coercion; pin updates invalidate address version. Existing order and seller-delivery view links to saved snapshot on OSM. Admin DTO remains private without location. Public map tile template configurable via VITE_MAP_TILE_URL; no new credential required for default OSM; replacement providers need attribution/usage-policy review.
