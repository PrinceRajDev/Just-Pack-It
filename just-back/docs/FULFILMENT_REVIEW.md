# Address and fulfilment review decision

`POST /cart/fulfilment` is authenticated and read-only. Strict body: `{addressId,shopIds:[uuid]}` (1–100 unique IDs). The address is resolved by session owner; missing/foreign IDs both return 404. No caller address fields, fee or ownership are accepted. This is independent of cart pricing and does not authorize checkout.

The server finds active service areas containing the saved pincode and checks each approved active shop's explicit area assignments. Pincode coverage is the current configured boundary; it does not promise a geocoded distance/radius. Active category membership is required. Hidden shops return only the requested ID and a generic unavailable issue. Pickup is allowed as a listed option independently of delivery pincode coverage; closed shops cannot currently fulfil either method. Seller delivery eligibility requires configured pincode coverage. Platform delivery remains unverified until dispatch capacity exists. Missing delivery fees remain null; even supplied fees are labelled listed fees, never a final quote. Pickup has a zero delivery fee. Shop minimum and stock remain in the separate cart review.

Response: `{checkedAt,addressId,addressVersion,checkoutAvailable:false,reserved:false,shops:[{shopId,options:[{method,status,listedFee,message}],issues:[{code,message}]}]}`. Status is `eligible|unavailable|unverified`; eligible means configured method checks passed at read time, not a reservation. Private no-store response, no account/address text or shop operational metadata. Future transactional checkout must re-read owned address, serviceability, current prices, quantities, shop minimums, chosen methods and delivery capacity, and snapshot accepted facts.
