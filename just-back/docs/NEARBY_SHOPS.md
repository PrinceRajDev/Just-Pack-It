# GPS discovery design

Explicit browser opt-in on first visit; no automatic native permission prompt. Browser coordinates are transient discovery input, never persisted as customer address or used to claim verified delivery. Manual service-area choice remains available. GPS mode lists approved active shops with real coordinates inside a fixed6km spherical radius and valid service/category assignments. Shops without coordinates are excluded; no geocoding guesses or invented coordinates. Distance is straight-line, not road distance/ETA. Checkout's existing address/service-area validation remains authoritative and unchanged.

Seller can save shop coordinates in shop profile; normal edits return to pending admin review. Admin reviews their accuracy before approval. Query radius cannot be expanded by client. Latitude and longitude must be supplied together and range-validated; cursor scope includes them. A resolve endpoint returns eligible service areas intersecting nearby shops. Automatically choose only if one area exists; otherwise ask which service area to browse. Precise buyer location is held in memory only, not localStorage or logs. Browser denial/timeouts/inaccurate fixes show honest fallback states.

No new API key, geocoder or paid map service needed. HTTPS or localhost is required for browser GPS. Seller/admin must collect actual storefront map pins; no existing shop coordinates were modified. Declared `Shop.location` 2dsphere index is included by existing `npm run db:indexes`; run this operator-reviewed migration before production. Development retains existing Mongoose auto-index behaviour. No Atlas migration was run. Discovery radius is not checkout delivery enforcement: manual area browsing and existing address-based checkout remain available by design. Public shop detail links can still be visited outside GPS browsing, so radius must not be represented as a delivery guarantee.

## Automatic area selection follow-up
Resolver now uses existing Shop.location 2dsphere index through bounded $geoNear (6000 m), eligible approved/active shop query, active assigned-area grouping and nearest-distance ordering with ID tie-break. Returns recommendedAreaId; client selects it only if present in eligible returned areas. Existing one-area fallback supports older API. This is nearest eligible shop coverage, not reverse geocoding or official administrative boundaries. Admin area name/pincodes alone do not create GPS coordinates: approved shops must be explicitly assigned and have accurate saved pins. No fixed default area.
