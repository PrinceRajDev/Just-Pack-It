# Seller alerts and order support
Design: seller orders poll every 15 seconds while visible; sound off by default, enabled by user gesture for the current screen only. First load establishes baseline, not a new-order event. Browser background delivery is not guaranteed; existing push remains separate.
Support: one durable ticket per owned shop-wise suborder, including cancelled/delivered orders. Buyer submits category and description; server derives shop/buyer/order identifiers. Duplicate submissions return the existing ticket. Admin can track open/in_progress/resolved with optimistic version and mandatory resolution note. No refund, cancellation or payment mutation. Notifications and ticket updates share transactions. Private responses exclude account/contact/address/payment secrets. Lists use ID cursor, 25 per page. No demo tickets are sent to real APIs.

Screenshots/report in just-front/docs/support-qa. Actual audible sound and background notification delivery were not manually verified. Existing broader followup-qa checkout runner timed out on pickup radio; that rerun remains failed/unverified, recorded separately. No live database, email, storage, payment or refund writes.
Operational dependency: normal MongoDB replica-set transactions. New SupportTicket indexes included in non-destructive db:indexes script, not applied to Atlas here. No API keys needed. One ticket per suborder; no attachments, threaded conversation, reopen or automatic refunds in this version. Alerts work while seller orders screen is open, 15-second polling; use existing opt-in push for background notifications.
