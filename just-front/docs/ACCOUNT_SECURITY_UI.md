# Account security controls

Connected `/account` now provides current-password-protected password change and sign-out-all for every role. New password requires a different 12–128 character value and matching confirmation; both actions require explicit acknowledgement that every device, including the caller, will be signed out. Demo account views are unchanged.

UI calls the auth service layer (`POST /auth/password`, `POST /auth/logout-all`), never direct fetch. Passwords exist only in component state and are cleared after completion/error/mode change; they are not persisted in app browser storage/query caches. A successful 204 clears the local session/private cached queries without sending an unnecessary second logout using the revoked token. The account then prompts for fresh sign-in. Incorrect-password errors keep the session and allow correction. Network/server/unknown or concurrent-credential outcomes do not claim success or retry automatically: controls lock and offer explicit local-session clearing and sign-in; the user should try the new password first when appropriate.

Other tabs invalidate their stale UI/private account state when the shared session storage changes. They do not delete a replacement session created by another tab. A stale bootstrap profile response cannot restore an invalidated session after a cross-tab revocation event. Backend auth-version verification remains authoritative; this is additional UX isolation, not client-side authorization.

Changed files: `src/services/auth.ts`, `src/stores/auth.tsx`, new `src/components/auth/AccountSecurity.tsx`, `src/components/auth/LiveAccount.tsx`, new account-security/session-revocation component tests, this document and contract notes. No real account password/session, backend credentials, payment flags, layout identity or routing library changed. Browser E2E of real account password changes is not performed in this step; component tests mock the API and backend endpoints were separately integration-tested with isolated users.

Validation: `npx tsc --noEmit`, 141 tests/31 files and production build passed. Full ESLint initially identified one test-mock formatting error alongside 22 existing Fast Refresh warnings; formatting was corrected and final `npx eslint . --quiet` passed with zero errors. Added tests cover confirmation, success-only local logout, incorrect-password handling, uncertain-result retry lock, private-cache cleanup, cross-tab replacement session preservation and stale bootstrap rejection. Test Link mock prevents jsdom navigation rather than attempting a real browser redirect.
