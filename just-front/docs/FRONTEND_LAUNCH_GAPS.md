# Frontend launch gaps — 2026-10-30

Scope: repository audit of frontend routes, domain types, config/API client, services, stores/mocks, connected buyer/seller/admin/delivery screens and API contract. No application code changed in this audit. This is a launch checklist, not a claim of exhaustive production certification. Existing pilot/test reports are supporting history only.

## Existing foundations verified in source
React/TypeScript, TanStack Router/Query, Vite; service/API boundary; explicit demo/connected mode. Category → area shops → owned shop catalogue, product variants, shop-grouped local cart, server checkout review, saved addresses, COD and Razorpay UI, order cancellation, receipt/cash confirmation, support tickets/refund states, email OTP/recovery UI, notifications/push opt-in. Seller owned products/variants/images/stock, approval flow and GPS draft capture. Admin approvals, taxonomy, service areas/readiness, orders, payments/refunds and support.

## Recommended implementation order
1. Buyer account gap: connected LiveAccount ignores account tab search, so header wishlist link does not render a wishlist despite working local save hearts. Add connected saved-items view; missing/deleted listing handling; label device-only persistence. Profile editing unavailable. Cart/wishlist storage keys are browser-wide rather than account-scoped; specify guest merge/account-switch policy before changing persistence.
2. Complete mobile checkout regression QA: earlier followup runner timed out at pickup selection. Do not infer product defect from runner alone; reproduce. Cover area switch with existing cart, address change, mixed shops, closed/stock-changed variants, offline submit, reload/double-submit/recovery and cancelled online checkout. Existing server review and idempotency not missing. Online order removes purchased cart lines at creation before capture: validate clear recovery/customer messaging for abandoned payment.
3. Buyer tracking UX: connected LiveOrders has status text/manual Refresh, no active-order polling/timeline/last-update or trustworthy ETA/rider details. Build honest shop-wise status timeline; no fabricated countdown or delivery promise. Full platform tracking requires delivery backend.
4. Location/address UX: current GPS recommends nearest shop area, not actual administrative boundary; shop pin and browser precision matter. Add editable buyer delivery pin/address confirmation, out-of-service clarity, change-area/reselect impacts; ensure fulfilment enforces intended distance policy server-side. Existing pincode/manual saved addresses and GPS address confirmation already present. No map picker/reverse geocoder currently.
5. Real-market information pages: no dedicated terms, privacy, cancellation/refund policy, delivery policy or business contact routes/footer links in current route inventory. Obtain approved business copy/contact details; do not invent legal terms or refund deadlines. This is product completeness finding, not legal advice.
6. Email/push/payment launch verification: UI exists but provider credentials, actual verified emails, real-device notification permission/background delivery and real Razorpay checkout/webhooks/refund need separate readiness verification. Do not count absent credentials as frontend implementation. Never bypass OTP to launch.
7. Catalogue performance: homepage loads productsQuery({}) and shopsQuery() before area filtering; catalogue service apiAll eagerly retrieves all cursor pages. Replace with area-scoped enabled queries and incremental UI pagination. Test low-end device/slow mobile, large catalogue and image resizing/cache behaviour. imageUrl passes absolute URLs through; no guarantee responsive variants are generated. No current performance budget/Lighthouse evidence.
8. Category-specific merchandising: generic attributes and independently priced variants exist; typed category-driven fields, food add-ons/preparation, clothing size-colour matrices, freshness/handling, warranties/compatibility and variant photos need scope. Do not force grocery fields universally.
9. Reorder: connected orders have no buy-again action despite metadata saying reorder. Revalidate exact shop/product/variant/stock/price before repopulating bag. Add printable order receipt/invoice only with actual seller/tax data.
10. Seller operations: connected dashboard is setup rather than daily operational overview. Offers/payout menus are hidden and respective direct routes return unavailable. Need low-stock queue/bulk stock workflows as appropriate, seller search/order urgency, working settlements after ledger exists. Current profile edits require reapproval including routine operational edits: review impact of changing hours/temporary closure.
11. Delivery workspace: connected RoleGuard deliberately shows unavailable for delivery role. Assignment, acceptance, pickup/drop progression, routing/contact policy, COD handling/earnings need backend plus UI. If launching seller delivery/pickup only, keep platform delivery promise absent from marketing/footer.
12. Admin operations: all-shop product moderation view not connected; category reactivation unavailable; loaded-array seller/shop/taxonomy filters have scaling limits. Stuck-order resolution/action ownership, shop verification evidence, support conversation/reopen/text search, settlement and audit explorer not implemented. Existing approval/taxonomy/orders/support features must not be duplicated.
13. Search quality: recent/typo helper exists; server matching differs from local suggestions, shop matches display at most four. Validate actual matching semantics, Hindi/local names, zero results, keyboard suggestions and large results. No claim of voice-search requirement.
14. Notifications: existing durable inbox and opt-in push are foundations; improve notification deep-link context and unread/seen semantics as needed. Real-device tests remain required.
15. Accessibility/browser QA: current Chromium smoke tests are not screen-reader/iOS Safari/Android real-device audit. Keyboard focus, error announcements, OTP paste, modals, zoom, safe-area and sticky add-to-bag need verification. React act warnings in GPS tests need cleanup; passing assertions do not remove warning.
16. Branding/copy: home title/metadata still grocery-centric despite multi-category model; connected copy repeatedly says phase/connected/debug concepts and footer advertises delivery workspace not connected. Align with actual launch scope; no full redesign needed.
17. Observability/release: no verified frontend error-monitoring, performance analytics/event funnel, full CI browser gate or accessibility/performance report in this audit. Add sanitized operational telemetry and test/release checks, excluding credentials/customer payloads.
18. PWA/installability optional: Firebase service worker exists, but no app manifest in public inventory. Push SW does not imply offline/installable app. Add only after shopping correctness; never show stale prices/stock offline as purchasable.

Launch blockers vs optional: if seller-delivery/pickup COD pilot, prioritize 1–7 and operational end-to-end QA. Online payment, platform rider delivery, promotions and settlements must have complete backend/provider support before advertised. Loyalty, subscriptions, wallet, voice search and gamification are optional, not launch prerequisites.
