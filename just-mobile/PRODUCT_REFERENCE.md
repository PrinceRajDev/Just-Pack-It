# Product Details reference implementation

Scope: the existing ProductCard modal is replaced with BuyerProductDetails. Card layouts, Home, Browse, Shop Details, routes, auth and shared bag stay in place. A nonvisual context provides area, shop metadata and account scope.

The supplied PNG is **440 × 1040**, despite the brief also specifying 440 × 844. The layout follows its proportions at 1040px height and scrolls above a fixed CTA on the shorter requested devices. The header, 392 × 254 gallery at 440px width, typography, pack pills, comparison container, footer and 56px CTA follow the reference. The modal has its own safe-area provider.

Data is live: the product is refreshed using its existing public endpoint; MRP/discount appear only when valid for the selected pack. A base MRP is used for a variant only when its normalized unit and price exactly match the base offer. Otherwise no variant MRP is invented. Single-image products show one indicator, not three duplicate images. Picked-today is shown only from a real tag; other products show stock status. Descriptions, photos, care information and availability come from actual data. No example sellers, ratings, ETAs or storage claims are inserted.

Comparison scans the existing paginated area product/shop APIs. Equivalent identity requires a shared barcode/GTIN/EAN/UPC, or an explicit identical brand plus exact normalized product name/category. Matching display names alone are insufficient. Pack normalization equates measurements such as 500g/0.5kg and 1000g/1kg, without guessing units for bare numbers. Only offers for the chosen pack appear. Seller switching preserves this pack key and builds the existing productId/variantId/shopId/price payload. Best-nearby-price is shown only for a complete comparison with multiple offers, using in-stock/open-shop data. A single seller has an explicit no-equivalent-offers note.

The heart uses existing encrypted native device storage, scoped by guest/account and product. No server wishlist endpoint exists, so this is not presented as cloud sync. Add calls the existing shared cart function, respects stock and announces success through the CTA.

Verification: real product GET was saved in ignored QA output, Expo web ran, and actual screenshots were inspected. This exposed zero-height horizontal gallery cells; explicit image-cell dimensions fixed it. The live case tests favourite persistence, real image rendering, single-seller behavior, Add and shared-bag navigation. Isolated HTTP fixtures (never production records) test two-image scrolling, MRP/discount, pack changes, two equivalent seller offers, preserved 1kg/1000g size, selected seller/variant payload and stock cap. Pure helper tests reject brand/barcode/pack mismatches. Viewports: 440×1040, 440×844, 390×844, 360×800, 375×812 and 430×932. Physical-device/checkout verification is not claimed.
